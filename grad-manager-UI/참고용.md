# API Specification & Data Contract

이 문서는 한신대학교 AISW/융합전공 맞춤형 학사 졸업 요건 관리 시스템인 **GradManager (졸업을 부탁해)** 프로젝트의 프론트엔드와 백엔드 간 API 규격서(Contract)이자, AI 개발 컨텍스트 가이드라인입니다.

---

## 1. Project Overview (프로젝트 개요)
- **목적:** AI·SW 전공 및 복잡한 특화/융합 전공 요건을 가진 한신대학교 학생들의 학업 이수 현황을 실시간으로 시각화(디지털 트윈)하고, 부족한 졸업 요건에 맞춤화된 AI 수강 과목 및 최적의 시간표를 설계해 주는 모바일-퍼스트 반응형 웹 서비스입니다.
- **핵심 가치:** 
  - 복잡한 다중 이수 경로의 간결한 시각화 (Digital Twin Circular Progress)
  - 조건 기반 AI 지능형 추천 시간표 및 수강 과목 매핑 (AI Recommendation)
  - 실시간 대화식 학사 이수 시뮬레이터 (AI Chatbot)

## 2. API Contract (API 엔드포인트 계약 규격)

### 2.1. 회원가입 (Sign-up)
- **Endpoint:** `/api/register`
- **Method:** `POST`
- **Request Payload:**
  ```json
  {
    "studentId": "2022115001",
    "password": "userPassword123",
    "name": "김한신",
    "department": "AI.SW학과"
  }
  ```
- **Response Format (200 OK):**
  ```json
  {
    "message": "회원가입이 정상적으로 완료되었습니다."
  }
  ```

### 2.2. 로그인 (Login)
- **Endpoint:** `/api/login`
- **Method:** `POST`
- **Request Payload:**
  ```json
  {
    "studentId": "2022115001",
    "password": "userPassword123"
  }
  ```
- **Response Format (200 OK):**
  ```json
  {
    "token": "mock-jwt-token-12345",
    "user": {
      "name": "김한신",
      "university": "한신대학교",
      "department": "AI.SW학과",
      "track": "본전공 + 특화전공(융합)",
      "studentId": "2022115001",
      "semester": "3학년 2학기",
      "mileage": 1280,
      "overallProgress": 72,
      "remainingCredits": 37,
      "totalRequired": 132,
      "earnedCredits": 95
    }
  }
  ```

### 2.3. 전역 졸업 진척 정보 로드 (Get Grad Data)
- **Endpoint:** `/api/grad-data`
- **Method:** `GET`
- **Headers:** `Authorization: Bearer <token>`
- **Response Format (200 OK):**
  - 응답 본문은 [public/data/grad-manager.json](./public/data/grad-manager.json) 포맷의 전체 JSON 구조를 상속합니다.

### 2.4. 유저 프로필 정보 수정 (Update Profile)
- **Endpoint:** `/api/user/profile`
- **Method:** `PUT`
- **Headers:** `Authorization: Bearer <token>`
- **Request Payload:**
  ```json
  {
    "name": "김한신",
    "studentId": "2022115001",
    "department": "컴퓨터공학과"
  }
  ```
- **Response Format (200 OK):**
  ```json
  {
    "success": true
  }
  ```

### 2.5. AI 시간표 설계 시뮬레이션 대화 (AI Chatbot)
- **Endpoint:** `/api/chat`
- **Method:** `POST`
- **Headers:** `Authorization: Bearer <token>`
- **Request Payload:**
  ```json
  {
    "message": "금요일 공강에 전공 9학점 맞춰서 시간표 짜줘"
  }
  ```
- **Response Format (200 OK):**
  ```json
  {
    "message": "요청하신 조건에 맞춘 분석이 완료되었습니다. 추천 시간표를 확인해 보세요."
  }
  ```

## 4. UI-Feature Mapping (UI 컴포넌트와 API 요구사항 매핑)

| UI Component | Tab / Screen Path | Required Backend API | Description |
| :--- | :--- | :--- | :--- |
| **LoginPage** | `/` (미인증 시) | `POST /api/login` | 세션 시작 및 JWT 토큰 획득 |
| **SignUpPage** | `/` (가입 탭) | `POST /api/register` | 신규 학생 계정 등록 |
| **HomeTab** | `홈` 대시보드 탭 | `GET /api/user` | 진행률, 카테고리 진척도 및 빠른메뉴 수급 |
| **DigitalTwinScreen** | `홈` -> 디지털 트윈 | `GET /api/digital-twin` | 졸업 가능성 시나리오 통계 로드 |
| **ScheduleTab** | `시간표` 탭 | `GET /api/recommendations` | 가상 생성된 최적 시간표 블록 렌더링 |
| **ChatTab** | `AI 추천` 메신저 탭 | `POST /api/chat` | 자연어 처리 기반 조건부 수강 설계 피드백 |
| **AiRecommendationScreen** | `AI 과목 추천` | `GET /api/ai-recommendation` | 관심사 태그 필터 기반 과목 카드 수급 |
| **NoticeTab** | `알림` 탭 | `GET /api/notice` | 공지사항 및 학사 일정 데이터 매핑 |
| **ProfileTab** | `마이페이지` 탭 | `PUT /api/user/profile` | 개인 신상 정보 수정 및 저장 |

## 5. AI Context Summary (AI 컨텍스트 정보)

향후 개발 세션의 AI 에이전트를 위한 컨텍스트 요약본입니다.

- **인증 생명주기:** 사용자의 로그인 세션은 `localStorage`가 아닌 브라우저의 `sessionStorage`에 보관됩니다. 이에 따라 브라우저 창이나 탭을 종료하면 인증 정보가 자동으로 소멸(임시 로그아웃)됩니다.
- **토큰 자동 삽입:** `lib/api.ts` 내부의 `apiFetch` 함수는 클라이언트 세션에 `token`이 있을 시 헤더에 `Authorization: Bearer <token>`을 자동으로 주입합니다.
- **상태 동기화 메커니즘:** 프로필 변경(`PUT /api/user/profile`) 발생 시, MSW 모의 서버(`lib/mocks/handlers.ts`) 내 인메모리 스토어 변수인 `tempProfileUser`가 업데이트됩니다. 이후 `getGradData` 겟 호출 시 데이터가 오버라이드 갱신되어 UI 전역에서 실시간 정보 일관성이 유지됩니다.
- **다크 모드:** Tailwind CSS `class` 기반 다크 스킨 변환 전략을 사용하며, `ProfileTab`에서 `documentElement.classList.add("dark")`를 제어해 즉시 스킨을 전환합니다.

## 6. Future TODO (향후 백엔드 연동 과제)

실제 데이터베이스 및 보안 서비스와의 연동을 완료하기 위해 백엔드 개발 시 우선적으로 다루어야 할 과제 목록입니다:

1. **실제 JWT 및 세션 만료 구현:**
   - 임시 하드코딩된 토큰 `mock-jwt-token-12345`를 대체할 실제 HMAC-SHA256 또는 RSA 기반 JWT 생성 및 검증 모듈을 연동해야 합니다.
   - 보안 강화를 위해 리프레시 토큰(Refresh Token) 및 세션 만료 만기 타임아웃 처리가 백엔드 레벨에서 연계되어야 합니다.
2. **학번/비밀번호 암호화 및 유효성 검사:**
   - 가입 및 로그인 시 평문으로 전달되는 비밀번호를 `bcrypt` 또는 `Argon2` 알고리즘으로 단방향 해싱하여 DB에 안전하게 보관해야 합니다.
   - 학번 고유값(Unique Key) 인덱싱 및 정규식 검증 모듈을 추가해야 합니다.
3. **디지털 트윈 시뮬레이션 산출 엔진 개발:**
   - 프론트엔드가 요구하는 `scenarioCount`, `aiProbability` 등의 시뮬레이션 지표를 학번 기준 누적 수강 정보와 연계하여 산출하는 백엔드 예측 로직(혹은 룰 엔진)의 실제 구현이 필요합니다.
4. **AI 시간표 생성 및 자연어 대화 모델 파이프라인 연동:**
   - `/api/chat` POST 요청 시 단순히 모의 문장을 리턴하는 구조를 탈피하고, LangChain이나 OpenAI API, 혹은 사내 LLM 모델과 실제 연동하여 프론트엔드로 파싱 결과를 전달해야 합니다.
